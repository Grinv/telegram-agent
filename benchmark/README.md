# Agent Benchmark

A repeatable measurement of what the agent costs (tokens, estimated cost, turns, tool calls) and whether it answers correctly, over a fixed set of tasks. See the main [README.md](../README.md#benchmark) for how to run it, what a snapshot contains, and how to compare two snapshots.

## The task set is frozen once a baseline exists

`tasks.ts` defines the fixed benchmark task set. **Once a baseline snapshot has been recorded, do not edit this file** (or `skills/word-count.md`, which one of its tasks depends on): editing a task's id, kind, turns, or correctness check changes the task set's identity (`task-set-id.ts`, computed from the tasks' content — see its doc comment), and `compare.ts` refuses to diff two snapshots whose task-set identity differs rather than presenting the difference as though it were the effect of an unrelated change (see the main README's [Benchmark](../README.md#benchmark) section and design.md's "Snapshots record their conditions, and the comparison refuses mismatches").

If a task turns out to be flaky (its correctness varies across repetitions with nothing else having changed), fix or remove it — but doing so after a baseline exists means every snapshot taken before the edit is no longer comparable to anything taken after it. Establish stability *before* recording the baseline (see the main README).

## Layout

- `types.ts` — the `BenchmarkTask` shape.
- `tasks.ts` — the fixed task set.
- `checks.ts` — reusable, pure correctness-check factories.
- `task-set-id.ts` — computes the task set's identity.
- `skills/` — a benchmark-only skill directory (kept separate from the bot's real `skills/`), used by the `word-count-skill` task.
- `in-memory-history-store.ts`, `capturing-replier.ts` — fakes the runner uses to drive the real message handler without touching a real chat or persisting history across executions.
- `runner.ts` — runs the task set against the real agent and reads back per-execution tokens/cost/turns/tool-calls from its own stats database.
- `with-sampling.ts` — wraps a `callLlm` so every call requests deterministic sampling.
- `snapshot.ts` — saves/loads a labelled run as a snapshot.
- `compare.ts` — compares two snapshots.
- `run.ts` / `compare-cli.ts` — the `npm run benchmark:run` / `npm run benchmark:compare` entry points.
- `Dockerfile` — builds the image the `benchmark` Compose service (`docker-compose.yml`) runs, for deployments where Ollama is only reachable on the internal Docker network. See the main README's [Benchmark](../README.md#benchmark) section.
- `baseline.md` — the recorded baseline reading (per-task tokens/turns/tool-calls/correctness), kept as the reference point for the token-optimization work. The underlying snapshot it was generated from (`data/benchmark-snapshots/baseline.json`) is local-only (gitignored); this file is the durable, committed record of what it showed.
